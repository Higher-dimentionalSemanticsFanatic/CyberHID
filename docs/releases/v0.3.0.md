## CyberHID 0.3.0

- Fixed: under Proton, axes that go below their middle (rudder pedals,
  toe brakes, sticks reaching the game through SDL) read only their upper
  half. Proton reports these axes as signed 32-bit values from -32768 to
  32767; CyberHID read them unsigned, so the lower half came out at the
  top of the range. Bindings scanned with 0.2.0 on such an axis may have
  **Invert** set the wrong way: scan them again.
- **Controllers**: axes show on the -1 to 1 scale of KDE's and SDL's
  controller settings (**Value (-1 to 1)**), next to the raw value from
  the device's input report (**HID value**, with the declared range on
  hover).
- A disconnected controller is listed once; the d-pad input is labelled
  **D-pad (hat)**.

Pre-release: the axis fix was checked against Proton's SDL report layout
in tests, not yet in game with the controller that showed it.
